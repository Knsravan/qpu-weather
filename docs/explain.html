1. What is this project, in one minute?

The idea

A quantum computer is a very sensitive machine. It makes mistakes, and how many it makes changes from day to day. IBM publishes a table of "how accurate each qubit is". That table is IBM's own measurement.

This project rides the bus and writes down what really happens: it runs small test programs on a real IBM quantum chip, measures the mistakes itself, and compares with IBM's table.

What it does each run

  1. Checks every qubit (156 of them) and every connection between qubits (176).
  2. Picks the best group of 5 connected qubits.
  3. Runs test programs whose right answer is known, and scores the result.
  4. Tries 4 "error fixes" and reports which one gets closest to the right answer.
  5. Saves the data; this dashboard updates itself.

How often

Automatically every Monday through GitHub, on a real IBM chip. IBM's usage page showed about 41 seconds of quantum time used (the owner's reading; not confirmed whether that is per run or for both test runs together).

A "qubit" is the quantum version of a bit. A "shot" is one run of a program; each program is repeated thousands of times and the outcomes are counted.

    5. Who is this useful for?

    Realistically useful for

    • People learning quantum computing who want to see real hardware numbers next to the datasheet.
    • Free-plan IBM users deciding which qubits to run on: it shows the best connected group that day and how much that choice helped.
    • Anyone curious whether a vendor's published numbers still hold on a given day.
    • The owner's portfolio: real hardware, real data, honest limits.

    Not useful for

    • Choosing between quantum vendors (only one IBM chip is tracked).
    • Research-grade error rates: some of the numbers are quick estimates (see the warnings in the dashboard tour).
    • Production workloads. It is a small monitoring project, not a product.

    6. What is actually new here (honestly)

    Short answer: nothing here is new science. It is a small, honest combination of things that exist separately. I checked this on 2026-10-11 with three quick web searches, which are not an exhaustive literature review.

    PieceAlready exists?What this project adds
    Re-running benchmarks regularly to track a device over time Yes Metriq (Unitary Foundation) re-runs standard benchmarks on a schedule. Not the idea itself.
    Drift of IBM chips from day to day Yes Academic studies show it, e.g. this 2022 paper. Not the discovery itself.
    Readout correction + zero-noise extrapolation beats either alone Yes Best-practices paper on ibm_washington found the same. Our result agrees with known work; it confirms, it does not discover.
    A public, automated page comparing IBM's reported numbers vs. independent measurement, per qubit, kept as history Not found I did not find a standing public dataset like this in one search. I cannot prove none exists. This is the honest gap: a small open tracker, with code anyone can rerun.
    The four error fixes ranked together on the same circuits, every run, on a free-plan chip Pieces exist Mitiq and papers compare fixes, mostly in simulation or one-off studies. A repeating, automatic measurement, with the winner shown on the dashboard.

    Honest framing for an interview: "an automated, open weekly check of a real IBM chip against its own datasheet, plus a measured ranking of error fixes. Incremental, with real data and honest limits." One more useful caution from the same searches: a 2026 preprint summary (not verified by me) suggests that on IBM's 156-qubit chips, extra measurement cost can outweigh the benefit of some error fixes when your shot budget is limited. Our scores do not test that.

    Sources: Metriq paper, IBM chip drift study, digital ZNE best practices, IBM: refresh backend properties.
